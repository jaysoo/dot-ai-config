## Moon

**Latest stable:** v2.4.6 (July 28, 2026)
**Prior stable at last scan:** v2.3.5 (June 26, 2026)
**v2.4.0 shipped:** July 5, 2026 (just outside July 6 scan start; v2.4.1+ are fully in window)

### Released this period

**v2.4.0 (July 5, 2026) -- CAS cache promoted to stable; task checks; Ruby toolchain**

- **CAS cache enhancements (promoted from experiment):** OS reflinks for file copying, cross-cache blob retrieval between local and remote stores, automatic local cache warming after remote hits. This is the predicted "CAS to stable" move from the July report.
- **Daemon modernization:** Advisory file locks replace PID-liveness checks for exclusive workspace ownership. Automatic idle retirement. Single-operation connection/startup. Daemon binary compatibility validation on client connect.
- **Task `checks` setting:** Pre-execution shell scripts that run with fingerprint, requirement, or condition types. New `mergeChecks` option. Top-level `taskOptions` for cross-project defaults.
- **Ruby toolchain (unstable):** Bundler-based, tiers 1-3.
- **Python:** Poetry package manager support (tiers 1-3).
- **VCS hardening:** Git command injection protection; improved rename detection (old path = deleted, new path = added).
- **CLI:** `--update-constraint` for `moon upgrade`; `--log` level refinement (debug vs trace).

**v2.4.1 (July 6): daemon startup fix when cache dir absent**

**v2.4.2 (July 8): workspace graph caching optimization; Go toolchain fix**

- Reduced plugin calls on cache hits in large workspaces.

**v2.4.3 (July 12): Renovate support; BitBucket codeowners syntax**

- Dependency serialization fix; CI provider branch detection; read-only cache file permissions fix.

**v2.4.4 (July 17): remote caching reliability fixes**

- Bazel RE contract validation failure fix; missing stdout/stderr handling; gRPC blob size cap raised to 4MB; HTTP cache read-only settings enforcement.

**v2.4.5 (July 19): HTTP remote cache manifest deserialization fix**

**v2.4.6 (July 28): MOON_BASE/MOON_HEAD without --affected; GitLab CI merge request HEAD fix**

### Key changes by category

- **Features:** CAS to stable (OS reflinks, cross-cache retrieval, auto-warming), task `checks`, Ruby toolchain (unstable), Python/Poetry
- **Performance:** Daemon advisory locks, workspace graph cache hit optimization
- **DX:** `--update-constraint`, cleaner `--log` levels, Renovate integration
- **Ecosystem:** Ruby + Poetry added; Bazel RE compatibility fix
- **AI:** None (no new MCP tools in v2.4)

### Nx implications

**Threat level: HIGH (escalated).**

1. **CAS promotion is the July report's predicted "next watch point" materializing.** Moon now markets local/remote cache format unification as a real shipping feature. The experiment flag is gone. Users who adopted the experiment have a stable path forward.
2. **Cross-cache blob retrieval** is a capability Nx does not have: a blob fetched from remote cache can populate local cache automatically, reducing repeat fetches. This is architecturally differentiated.
3. **Task `checks` (pre-execution fingerprinting)** adds a layer of conditional execution Nx lacks. Useful for "only run this if X toolchain is present" patterns.
4. **Ruby toolchain** expands Moon's polyglot story. Combined with existing Go, Java, and Python support, Moon's breadth now matches or exceeds Nx's non-JS plugin story in several languages.
5. **MCP tools: still no new additions in v2.4.** The June v2.3.0 MCP tools (`get_template`, `get_templates`) remain Moon's AI story. No new MCP expansion this cycle. Nx has a window to catch up on MCP generator discoverability.

## Turborepo

**Latest stable:** v2.10.8 (July 31, 2026)
**Prior stable at last scan:** v2.10.3 (~July 3, 2026)
**New stable minors this period:** v2.10.6 (July 22), plus v2.10.7/v2.10.8 (both July 31)

### Released this period

**v2.10.6 (July 22, 2026) -- Cargo/Rust workspace support**

- **Cargo workspace task inference:** Turborepo now discovers and infers tasks within Cargo workspaces. "Cargo-only repos" (no JS package manager) are supported.
- **Output resolution:** Handles Cargo profile output and target layout correctly.
- **Disabled unresolved Cargo artifact caching** to prevent build corruption.
- Bun production workspace dev-dependency pruning.
- pnpm `node@runtime:` lockfile entry preservation during prune.
- Yarn Babel extension preservation during prune.
- TUI color output fixes.
- Rust toolchain bumped to 1.97.0.
- Security dependency updates (brace-expansion, tar, js-yaml).

**v2.10.7 (July 31, 2026) -- pnpm aliased dep preservation; macOS file watching**

- Preserve pnpm root and aliased dependencies during prune.
- Multiple macOS file watch roots now supported.
- "Package knowledge" architectural refactoring begins: authoritative package scope views.
- Release process resumability.

**v2.10.8 (July 31, 2026) -- "Package knowledge" major refactor; UV Python; Android support**

- **"Package knowledge" refactoring completed:** New abstraction for modeling project structure. Used for configuration scopes, run scope enumeration, task hashing paths, run-cache paths, and MFE commands. This is an architectural foundation shift.
- **UV Python workspace support:** Native task execution, lockfile hashing, file watching, and workspace pruning for UV Python environments.
- **Android/Termux support:** Turborepo now runs on Android via Termux.
- **Resolution fingerprinting** for task hashing: tracks how external dependencies resolve.
- **GitHub Actions remote base ref resolution** (behind feature flag): improved CI branch detection.
- TUI mouse wheel scrolling for task list.
- Telemetry salt caching (perf: reduces config reads during hashing).
- Cargo metadata snapshots reused for discovery efficiency.

### Key changes by category

- **Features:** Cargo workspace support, UV Python workspace support, Android/Termux support
- **Performance:** Resolution fingerprinting, telemetry salt caching, Cargo snapshot reuse
- **DX:** TUI mouse wheel, package knowledge abstraction (invisible to users but affects correctness)
- **Ecosystem:** Rust/Cargo, Python/UV, Android (major polyglot expansion)
- **AI:** None. `experimentalCI` object remains undocumented (18+ weeks since first canary).
- **Security:** brace-expansion, tar, js-yaml dependency updates (v2.10.6)

### Nx implications

**Threat level: HIGH (elevated).**

1. **Cargo/Rust and UV Python support is a direct move into Nx's polyglot differentiation.** Turborepo v2.10.6/v2.10.8 now supports Rust (Cargo) and Python (UV) workspaces natively. Nx's @nx/rust and Python support have been a differentiator; Turbo is closing this gap. Watch for "Turbo in a Rust+JS monorepo" evaluation posts.
2. **"Package knowledge" refactoring is an architectural investment** analogous to Nx's project graph model. If Turbo completes this migration, it gains a more correct and queryable project model. Resolution fingerprinting improves cache correctness for dependency-heavy repos.
3. **Android/Termux support** is a curiosity, not a strategic threat. Low urgency.
4. **`experimentalCI` is 18+ weeks undocumented.** If it surfaces as a "Turbo Cloud" or "managed CI" product, it competes with Nx Cloud DTE. Still the most significant unknown.
5. **Local cache eviction (v2.10.0 from June) remains an Nx gap.** No change this cycle; still unaddressed by Nx.

## Cross-Competitor Themes (August 2026)

1. **Polyglot is the new battleground.** Turborepo (Cargo/Rust + UV Python), Moon (Ruby + Poetry), Pants (uv, Go module granularity), Bazel (remote exec reliability) all shipped language-expansion features this cycle. Nx's polyglot story is no longer a clear differentiator; Turbo specifically is closing the gap on Rust and Python.

2. **Cache architecture investment continues across the board.** Moon promoted CAS with cross-cache retrieval and OS reflinks. Turbo shipped resolution fingerprinting. Both are making caching smarter with less explicit configuration. Nx's input model is still the most explicit.

3. **Vite+ pacing slows vs. expectations.** Three small releases, no remote cache, no stable `vite-task`. The Cloudflare acquisition (June) has not yet unlocked a cloud product move. Vite+ is shipping good incremental DX, but the "monorepo platform" story has stalled.

4. **Turbo `experimentalCI` remains the biggest unknown (18+ weeks).** Whatever is behind that feature flag is the next major Turbo reveal. At 18 weeks of canary-only existence without documentation, it is either delayed, blocked, or waiting for a coordinated launch. If it is "Vercel-managed CI with DTE," it competes directly with Nx Cloud.

5. **Moon v2.4 is the most complete minor release of the competitive cycle.** Six point releases in 23 days, major CAS promotion, daemon overhaul, task checks, two new language toolchains. Moon is the most actively shipping competitor right now in terms of strategic surface area.

## Recommended Actions (August 2026)

**High urgency:**

1. **Respond to Turbo's polyglot expansion (Cargo + UV Python).** Turborepo is no longer JS/TS-only. Evaluate whether Nx's Rust and Python plugin stories need a feature refresh or positioning update. "Nx is the only JS monorepo tool that supports Rust" is no longer true.
2. **Audit Nx cache implementation for path traversal and manifest manipulation (now 7 weeks outstanding).** Two competitors patched this on June 10. Escalate.
3. **Evaluate Vite+ auto input fingerprinting (carryover).** Still the most significant new DX gap. Three months after beta launch, `vite-task`'s fingerprinting is shipping to real users. Time to benchmark.

**Medium urgency:**

4. **Benchmark Nx remote cache against Moon's cross-cache blob retrieval.** Moon CAS (v2.4.0) automatically warms local cache from remote hits. This reduces repeat fetches in shared-dev scenarios. Evaluate if Nx Cloud can/should match this.
5. **Add local cache size/age eviction controls to Nx backlog.** Turbo `cacheMaxAge`/`cacheMaxSize` is now 5+ weeks old and will appear in comparison posts. A `cache.maxAge`/`cache.maxSize` option in `nx.json` closes the gap.
6. **Track Turbo `experimentalCI` (18+ weeks).** Still the biggest unknown. If it surfaces as "Vercel-managed CI with DTE," it is Nx Cloud's most serious competitive threat. Assign a watcher.
7. **MCP generator discoverability (carryover).** Moon `get_template`/`get_templates` (v2.3.0) with no new expansion in v2.4 -- Nx has a window to match or exceed this.

**Low urgency / monitoring:**

8. **Watch for Cloudflare remote cache product.** Still unannounced 2 months after acquisition. The longer it takes, the less likely it threatens Nx Cloud near-term.
9. **Pants v2.33.0 stable:** Shipped August 1. No JS/TS crossover. Light tracking continues.
10. **Moon Ruby toolchain (unstable):** Not an Nx concern until it stabilizes, but broadens Moon's polyglot reach.
11. **Consider `@nx/vite-plus` integration opportunity.** Cloudflare's stated open-source commitment makes a first-party Nx+Vite+ integration plausible. Would capture users who adopt Vite+ but want Nx's DTE/generator story.
