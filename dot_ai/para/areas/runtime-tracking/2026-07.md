### Risks for Nx

- **Security release July 27 (HIGH, TODAY)**: New 22.x/24.x/26.x security patches releasing today with HIGH severity. Nx CI matrices pinned to pre-patch versions will need updating as soon as patch versions are published. Watch nodejs.org/en/blog/vulnerability for CVE disclosures.
- **Security release June 18 (HIGH)**: Any Nx CI matrix still on pre-June-18 versions is exposed to CVE-2026-48618 (TLS hostname bypass) + CVE-2026-48933 (WebCrypto AES DoS).
- **`--experimental-import-text` now in Node 26.5.0**: TC39 Import Text (Stage 3) ships behind a flag. When it graduates to Stage 4, Nx generator template loading could use native `import with { type: 'text' }` instead of `fs.readFileSync`.
- **`Stats.Date` now enumerable (v24.18.0)**: `fs.stat()` results now expose `atime`, `mtime`, `ctime`, `birthtime` as enumerable. Any Nx serialization code that spreads or JSON-stringifies `Stats` objects may produce unexpected extra fields.
- **`--permission` stable (v24.18.0)**: Nx task sandboxing docs that reference `--experimental-permission` need updating. The `--experimental-` prefix is removed.
- **Node 26 `node:vfs` (experimental)**: A virtual file system API is landing in Node 26. Relevant to Nx's in-memory project graph and daemon file watching -- track for potential native replacement of current VFS layer.
- **Node 26 Package Maps**: The loader now implements package maps (import maps for CJS/ESM resolution). Could simplify Nx plugin resolution or conflict with existing alias handling.
- **Node 20 at 88 days post-EOL**: No upstream CVE coverage. The two HIGH CVEs from June 18 AND today's HIGH release are unpatched on any Node 20 installation.

### Opportunities

- **`readFile()` caller-supplied buffers (v26.4.0)**: Memory-efficient file reading for large workspaces. Relevant to Nx project graph serialization.
- **`Buffer.poolSize` 64K default (v24.18.0)**: Improved throughput for small buffer allocations common in CLI I/O.
- **Node 26 LTS in October 2026**: The Current line becomes LTS this October. Start planning Nx CI matrix update: add v26 as primary, v24 as secondary, v22 as minimum.

## Bun

### Releases since 2026-06-01

No new STABLE releases. The 54-day gap since v1.3.14 (2026-05-13) was explained on July 8: **Bun was rewritten in Rust** and v1.4.0 is under development as the first Rust-based release.

| Version | Date | Key Changes |
|---------|------|-------------|
| v1.3.14 | 2026-05-13 | Last Zig-based stable release |
| v1.4.0-canary | 2026-07-08+ | First Rust-based build; available via `bun upgrade --canary` only |

### Bun Rust Rewrite (Major Development -- July 8, 2026)

- **Anthropic acquired Bun** in December 2025. Jarred Sumner and the Bun team now work at Anthropic.
- Sumner rewrote the entire Bun codebase (~535,000 lines) from Zig to Rust **in 11 days** using Claude Code with 64 parallel Claude agents (PR #30412 on oven-sh/bun).
- Estimated API cost: ~$165,000. Equivalent human effort: ~3 engineers for 1 year (without AI).
- Result: passes Bun's test suite at ~99.8% compatibility on Linux x64 glibc. Binary shrinks 3-8 MB. Benchmarks neutral to faster.
- **Controversy**: Andrew Kelly (Zig creator) called the output "unreviewed slop." Open debate in the community about AI-generated code quality at this scale.
- **Current status**: Rust-based code ships only in canary. v1.3.14 (Zig) remains the stable channel.

### Nx compat status

- **Lockfile bug #16252**: 8+ months open, 0 assignees. **With the Rust rewrite complete and a new team under Anthropic, this bug may finally get attention.** Monitor for first triage or PR against the Rust codebase.
- **v1.4.0 canary**: Advise against testing Nx on Bun canary until stable. Zig->Rust transition may surface new compat issues not caught by Bun's test suite.
- **Test orchestration** (1.3.13 `--parallel/--isolate/--shard/--changed`): No new movement, but Anthropic ownership creates a potential pathway for tighter Nx-Bun integration as Claude Code embeds Bun.
- **Zig bindings downstream**: Third-party Zig FFI bindings to Bun are broken by the rewrite. Not a direct Nx concern but signals ecosystem disruption.

**Risk level for Nx: MEDIUM (upgraded from LOW due to ownership + rewrite disruption)**. No stable release yet, but the Rust rewrite resolves the silence mystery and sets up a new Bun era.

- **Node-API v10** (v2.9.0): Higher-level native addon support. Narrows the Node.js binary extension gap.
- **aarch64-pc-windows-msvc** (v2.9.3): Deno now has a Windows ARM compile target. Widens cross-platform reach.
- **Node compat (2.8.x/2.9.x)**: Continued HTTP/HTTPS proxy improvements, `node:http` and TLS fixes. Deno's Node compat layer is maturing rapidly.

**Risk level for Nx: MEDIUM** (unchanged from July 6; framework-aware HMR confirms Deno is targeting frontend dev workflows but Nx's task graph + distributed execution remain differentiated).

## Nx Status

### Version

**nx@23.0.x** -- major version released June 16-23, 2026. Patch releases (23.0.1, 23.0.2+) continue. Evidence of 23.1.0 in canary as of late July 2026 but not confirmed stable.

Key Nx 23 features relevant to this scan:
- **Native TypeScript loading + V8 compile cache on by default**: Aligns with Node 24.15+ `module.enableCompileCache()` stable. Potential startup speedup.
- **Task sandboxing (OS-level)**: Uses Node.js file system APIs at a deeper level. The `--permission` flag stability in Node 24.18+ is directly relevant.
- **Agentic `nx migrate`**: AI-assisted multi-major migration. Relevant to the Decorators regression risk -- an automated migration assistant reduces the blast radius of TC39 spec changes.
- **Breaking changes**: Numerous deprecated generators/executors removed. Full list in the GitHub release post.

### `engines` Field Review

**State re-verified 2026-07-27**: Field still absent from published `nx@23.0.x`.

`engines` field is **still missing** in published `nx@23.x`. **9th consecutive scan without this field.** Note: there is a GitHub issue (#5896 "Nx should define supported Node.js versions") that has been open for years. Also #31087 shows that npm itself warns "node v23 is unsupported engine" for Nx@21, suggesting the field may have existed at some point in older versions. The current 23.x line has no `engines` constraint published.

| Node 25 | **EOL (56 days)** | Remove from test matrix if still present |

Then add a runtime deprecation warning for Node 20 in Nx 23.x. Bump to `>=24.0.0` when Node 22 enters EOL in April 2027.
