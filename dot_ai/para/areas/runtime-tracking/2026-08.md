### Risks for Nx

- **CVE-2026-58043 (HIGH - Permission Model path over-grant)**: Nx task sandboxing uses `--permission` (now stable in v24.18). A radix-tree prefix bypass means sandboxed tasks can read/write outside their declared paths. Upgrade CI to v22.23.2/v24.18.1/v26.5.1 before relying on sandboxing for security isolation.
- **CVE-2026-56848 (HIGH - HTTP/2 heap-use-after-free)**: The Nx daemon uses long-lived HTTP/2 connections to Nx Cloud. All currently active daemon processes on unfixed Node versions are vulnerable.
- **CVE-2026-58040 (MEDIUM - incomplete June fix)**: TLS session reuse hostname-skip is a re-opening of the June 18 CVE-2026-48934. Nx Cloud connectivity goes over HTTPS; validate fixed node version in all deployment targets.
- **CVE-2026-56846 (HIGH - HTTP/2 maxSessionMemory bypass)**: Remote memory exhaustion risk for any Nx Cloud service or agent running as an HTTP/2 server on Node 22 or 24.
- **CVE-2026-58044 (LOW - HTTP request smuggling)**: Nx Cloud API calls proxied through load balancers could be smuggling targets if the proxy and Node disagree on Content-Length.
- **Pattern**: 2nd security release in 6 weeks (June 18 + July 29). Combined: 23 CVEs, 5 HIGH. Node.js TLS and HTTP/2 have been under sustained attack surface review. Pin CI to named security releases, not just major.minor ranges.

### Opportunities

- **`--experimental-import-text` (v26.5.0)**: Import text files directly as ES modules. Relevant to Nx generator template loading -- could replace `fs.readFileSync` calls in generators.
- **Native addon import default (v26.5.0)**: No longer requires `--experimental-require-module` for native .node imports. Simplifies any Nx native binding (e.g., watcher, daemon) on Node 26.
- **`blob.textStream()` (v26.5.0)**: Streaming blob-to-text conversion. Relevant to Nx's large file handling in cloud artifact upload.
- **Node 26 LTS in October 2026**: Two months out. Begin planning CI matrix promotion: v26 -> primary LTS, v24 -> secondary, v22 -> minimum. Node 26 is Current and already receiving security patches.

## Bun

### Releases since 2026-07-06

None (stable). Last stable release: **v1.3.14** (2026-05-13) -- now **82 days** without a stable release.

### Notable: Rust rewrite in canary

- **v1.4.0-canary**: AI-driven rewrite from Zig to Rust, merged May 14, 2026.
  - 1M+ lines of Rust landed in one batch commit.
  - Cost: ~$165K in Anthropic API calls over 11 days (May 3-14).
  - Available via `bun upgrade --canary` only.
  - Stable 1.3.x continues shipping from the Zig codebase.
  - No public commitment on when canary becomes stable.
- **Controversy**: Downstream Zig bindings (community native extensions) are at risk; the rewrite breaks the Zig extension API.
- **Why the release gap**: The Rust canary is the reason -- the team is stabilizing a near-complete runtime rewrite, not just cutting patches.

### Nx compat status

- **Lockfile bug #16252** (broken Yarn lockfile for workspace deps): Still open, 82+ days without a patch. The canary does not resolve it (different codebase layer). Primary Nx-on-Bun blocker unchanged.
- **Rust rewrite compatibility unknown**: The canary has not been publicly tested against Nx workspaces. When 1.4.0 goes stable, a fresh Nx compat pass will be needed.
- **Package manager changes in 1.4**: Unknown -- no stable release notes yet.

**Risk level for Nx: MEDIUM** (unchanged). No regressions, but no progress on the lockfile bug; Rust rewrite introduces unknown compat surface when it stabilizes.

- **Raw ChaCha20 (2.9.4)**: Low-level crypto parity with Node.js. Continues Deno's Node.js API surface convergence.
- **V8 upgraded to 150.2.0** (per earlier search result from 2.9.x): Higher V8 than current Node 24 LTS. Deno continues to ship newer V8 faster than Node LTS.

### Engines Field Policy (clarified this scan)

After 9 consecutive scans flagging the missing `engines` field as a bug, this is confirmed as **intentional policy**:
> Nx intentionally does not include an `engines` field in package.json to allow user flexibility. An official compatibility matrix is provided instead.

**Action change**: Stop tracking `engines` absence as a risk item. Instead, verify the compatibility matrix doc stays accurate as LTS lines shift. Specifically:
